# Плавная миграция с amnezia-wg-easy на awg-agent

**Одной командой** (автодетект контейнера, портов, подсети, переноса ключей и параметров обфускации):

```bash
sudo ./migrate-from-wg-easy.sh --dry-run   # разведать и показать план, ничего не менять
sudo ./migrate-from-wg-easy.sh             # мигрировать (спросит подтверждение)
sudo ./migrate-from-wg-easy.sh --rollback  # вернуться на amnezia-wg-easy
```

Скрипт: находит старый контейнер, читает его окружение (имена переменных у панелей совпадают) и `wg0.json`, копирует состояние в каталог awg-agent, пишет `docker-compose.yml` с `AWG_PROTO=2`, останавливает старую панель (не удаляя — для отката), поднимает agent и проверяет `/api/health`; при сбое откатывается сам. Проверено на awg.de (11 клиентов, набор 2.0) в режиме `--dry-run`.

Ниже — что именно переносится и ручная процедура, если нужно вручную.

---

Проверено на awg.de (awg-tools 1.0.20210914, набор параметров 2.0). Клиенты продолжают работать **без перевыпуска конфигов** — если сохранить ключи, параметры обфускации, порт и подсеть.

## Что обязано совпасть, чтобы клиенты не отвалились

| | Как сохраняется |
|---|---|
| Ключи сервера и клиентов, PSK | переносятся импортом из `wg0.json` как есть |
| Параметры обфускации `Jc/Jmin/Jmax/S1/S2/H1..H4` | переносятся импортом как есть, интерфейс держится на `proto=2` (без `S3/S4`, `HeaderProtectionKey`, `I1`) — иначе рукопожатие у старых клиентов ломается |
| `ListenPort` | задать `WG_PORT` = порт старой панели (у awg.de `40000`) |
| Подсеть и адреса клиентов | адреса переносятся импортом; сервер поднять в той же подсети через `WG_DEFAULT_ADDRESS`/`WG_SUBNET` (у awg.de `10.8.1.0/24`, сервер `10.8.1.1`) |

Код импорта (`agent/state.py::_import_legacy`) теперь переносит `Jc/S1/H1..H4` verbatim и ставит `proto=2` + `i1=None`. Сверка на реальном `wg0.json` awg.de: сгенерированный конфиг сервера **побайтно совпал** по всем 9 параметрам обфускации.

## Процедура для awg.de

```bash
# 1. Забрать старое состояние (ключи/клиенты/параметры)
sudo cp /opt/amnezia-wg-easy/awg-1/wireguard/wg0.json /opt/awg-agent/data/wg0.json

# 2. Остановить старую панель (WG уйдёт на секунды)
cd /opt/amnezia-wg-easy && sudo docker compose down

# 3. Поднять awg-agent тем же compose, с окружением под старый сервер:
#    WG_PORT=40000            ← ListenPort старой панели
#    WG_HOST=45.131.213.86
#    WG_DEFAULT_ADDRESS=10.8.1.x   (+ WG_SUBNET=10.8.1.0/24)
#    AWG_PROTO=2              ← новые клиенты тоже в наборе 2.0 (совместимо с парком)
#    PASSWORD_HASH=...        ← пароль панели
#    volume: /opt/awg-agent/data:/etc/amnezia/amneziawg   ← сюда положен wg0.json из шага 1
sudo docker compose up -d
# В логе: "миграция: параметры обфускации 2.0 сохранены — клиенты работают без перевыпуска"
```

Старые клиенты подключаются со своими прежними конфигами. Новые выдаются уже через awg-agent (в наборе 2.0, чтобы парк был однородным; при желании позже — перевод на 3.1 с перевыпуском).

## Проверка

- `GET /api/health` → `up: true`, число клиентов = 11.
- Клиент со старым конфигом переподключается (latestHandshake свежий).
- Обфускация в новом `wg0.conf` совпадает со старым: `Jc/Jmin/Jmax/S1/S2/H1..H4`.

## Откат

`docker compose down` агента → поднять обратно amnezia-wg-easy (его данные в `/opt/amnezia-wg-easy/awg-1/wireguard` нетронуты). Возврат мгновенный.

## Ограничения

- Пауза на переключение контейнера — секунды (WG down→up), не разрыв ключей.
- Мигрированный сервер остаётся на обфускации 2.0 (как и был). Апгрейд до 3.1 — только с перевыпуском конфигов клиентам, отдельным шагом.
- Если у старой панели в `wg0.json` нет параметров обфускации — агент сгенерит новые, и тогда клиентам нужен новый конфиг (в лог уйдёт предупреждение).
